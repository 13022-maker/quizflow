# Story Context

教育內容常見的故事包裝很弱：要嘛是「然後...然後...然後」的流水帳，要嘛塞了太多字讓學生沒空寫正事，要嘛敘事者一直跳出來說教。這個 skill 提供三個具體、可檢查的寫作原則，把故事情境壓縮到「精簡但有張力」。

## 核心原則 1：南方公園因果鏈公式（禁止「然後」）

《南方公園》編劇 Trey Parker / Matt Stone 的寫作規則：故事大綱裡每個事件之間只能用「**但是**」或「**因此**」連接，不能用「**然後**」。「然後」串起來的是沒有張力的流水帳；「但是」製造衝突轉折，「因此」製造因果推進。

套用到出題情境的最小模板（2-4 個 beat）：

```
[情境設定] 但是 [卡住的問題/衝突] 因此 [題目/任務要解決的缺口]
```

範例（環保交通工具主題）：
> 班上要在校慶擺攤介紹自己設計的環保交通工具。**但是**評審規則出了狀況——有的介紹卡寫得清楚，有的太籠統，分不出高下。**因此**小組要先幫忙評出問題所在，再合力寫出一份範例等級的完整介紹。

寫完故事草稿後自我檢查：把每個句子之間的連接詞圈出來，只要出現「然後」就要改寫成「但是」或「因此」其中一種因果關係。

## 核心原則 2：閱讀時間預算（不能吃掉作答時間）

故事情境是拿來讀的，不是拿來寫的——讀故事的時間必須從任務本身的時限裡扣，所以要嚴格控制長度。

- 預設閱讀速度：中小學生默讀繁體中文抓 **280 字/分鐘**（保守值）
- 故事情境只能佔該回合時限的 **10%**，且不論回合多長都有硬上限
- 公式：`storyBudgetChars = clamp(floor(min(該活動各回合秒數) / 60 * 280 * 0.10), 50, 200)`
- QuizFlow 批閱題組（review set）預設 `reviewDurationSec=600`、`createDurationSec=300`，取較短者 300 秒 → 預算約 **140 字**，實務上抓「150 字以內」
- 若題型/活動沒有明確回合時限（例如一般 AI 出題），故事情境一律控制在 **100-150 字**，當作安全上限

字數是寫給故事情境本身（情境鋪陳段落），不含題目本文/選項/範例答案內容。

## 核心原則 3：以物觀物（不說教、不投射情緒）

邵雍《皇極經世·觀物內篇》：「以物觀物，性也；以我觀物，情也。」——以物觀物是照著事物本身的性質/邏輯去呈現，以我觀物是把敘事者自己的主觀情緒投射上去。

寫故事情境時：
- **不要**：「光合作用真是太神奇了，讓我們一起讚嘆大自然的奧妙！」（敘事者在說教、在替讀者決定該有什麼感受）
- **要**：「葉綠體在光照下把水和二氧化碳轉成醣類，光照角度會直接決定轉換效率。」（照事物自己的因果邏輯呈現，讀者自己感受）

檢查方式：故事情境裡如果出現「真是太、讓我們、你一定會、多麼、值得學習」這類替讀者代言感受的詞，都是「以我觀物」的訊號，要改寫成描述角色/事物實際做了什麼、發生了什麼因果，把感受的空間留給讀者（或作答的學生）。

## 套用到 QuizFlow

寫故事情境型 AI prompt（例如 `src/lib/ai/reviewSetGeneration.ts` 的 `buildReviewSetPrompt`、或 `src/lib/ai/prompts.ts` 的出題 prompt）時，在給 AI 的指示裡明確列出這三條，而不是只說「加一個故事情境」：

1. 用「但是/因此」因果鏈寫 2-4 個 beat，不能出現「然後」流水帳
2. 故事情境本身壓在 150 字以內（依該活動實際回合時限套公式，沒有時限就抓 100-150 字）
3. 只描述情境中人事物實際做了什麼/發生了什麼，不加「太神奇了/讓我們一起」這類敘事者主觀評論或說教語氣

範例答案（samples）內容要延續故事世界觀（同一個情境裡的角色寫的東西），但一樣要遵守原則 3：範例答案本身也是角色做了什麼/寫了什麼的具體內容，不是掛評語的心得文。
